## Description

On start, compare each thread's `projection_state.log_length` against the real log and replay the gap. A crash between a log write and a database write leaves exactly this gap, and closing it on startup is what makes the asynchronous projection safe.

The scan has to stay cheap with ten thousand threads on disk. Reading an index header is 32 bytes and a `stat()` is free, so this is a directory walk rather than a full open of every thread.

## Acceptance criteria

- [ ] A thread whose log is shorter than its projection_state is reported as corruption rather than silently accepted
- [ ] Catch-up is idempotent if the process dies partway through it
- [ ] A gap between projection_state and the log is closed before the listener accepts requests (the server does not serve while catching up, decided in grooming 2026-09-24), and the catch-up logs how many threads it closed and how long it took
- [ ] Catch-up over ten thousand threads with no drift completes in under 2 s on the CI runner without opening every log, enforced by a test or benchmark that fails above that bound

## Implementation plan

Pre-groom plan (2026-09-24). Revise at claim, after reading the code as it stands then.

Decided: catch-up finishes before the listener accepts requests. The target is 10k threads with no drift in under 2 s on the CI runner. Lag goes to the log and to healthz. Write this into docs/03 "Durability and recovery" as AC1's "written down" part.

### Approach
1. `projection.CatchUp(ctx, db, root, w *Writer) (Report, error)` lives in `internal/events/projection/catchup.go`. It runs ONE query, `SELECT thread_id, log_length FROM projection_state`, into a map.
2. Walk `threads/xx/yy/` with `os.ReadDir`, two levels, following the `threadid` layout. For each `*.log`, use `threadid.FromLogPath` for the id and `DirEntry.Info().Size()` for the size. No log is opened on this pass. Sizes come from stat, which is what "without opening every log" means here.
3. Classify each thread. `size == projected` means no drift. `size > projected`, or no row at all, means a gap; call `w.ProjectThread(ctx, id, size)`. `size < projected` means corruption: log at error with the thread id and both lengths, count it in `Report.Corrupt`, and do NOT rewind or re-project. A `projection_state` row with no log file on disk is also reported.
4. The torn-tail case: `ProjectThread` scans to `size`, and `ScanFramesFrom` stops at a torn final frame, so the projected length is the last good boundary. The next open through threadcache truncates the tail. The two agree.
5. Each thread's gap is closed in its own transaction, the one `ProjectThread` already uses. Dying partway leaves every finished thread consistent and every unfinished one still showing a gap. A rerun resumes. That is the idempotence AC.
6. Parallelism: the stat walk is sequential. Gap replays run on a small worker pool, bounded by the DB write pool of 1, so in practice they run serially. Measure before adding workers.
7. Log one summary line: threads scanned, gaps closed, bytes replayed, corrupt, elapsed. Expose `Report` so healthz and the metrics endpoint can read the last value. The same function is the `Sweep` hook C2WW5 calls on `Batch.Dropped > 0`.

### Files and packages
New: `internal/events/projection/{catchup.go,catchup_test.go}`. Reused: `threadid.FromLogPath` and `ID.Dir`, `threadlog.FileHeaderSize`, `Writer.ProjectThread` from C2WW5, `db.DB.Read`. Touched: docs/03 "Durability and recovery" (the decision). Serve (CCBYX) calls CatchUp between DB migrate and `bus.Start`. `Bus.Publish` before Start is a no-op, so nothing races it.

### Tests
- AC1: `TestServeWaitsForCatchUp` lives in the CCBYX serve test. It creates a data dir with a gap, starts serve, and asserts that when the ready signal fires, `projection_state` equals the log sizes. Here in the package: `TestCatchUpClosesGap`.
- AC2: `TestCatchUpTenThousandNoDrift` generates 10k minimal valid logs, a 64-byte header each (fast to write), with matching projection_state rows. It asserts elapsed < 2 s, and zero opens through an injected opener hook. This runs under `-race` in CI, which may exceed 2 s. If it does, move the timing assertion to a separate non-race CI step, like the property sweep, and keep the no-open assertion under race.
- AC3: `TestLogShorterThanProjectionIsCorruption` checks that Report.Corrupt == 1, that the row is unchanged, and that the error log line names the thread.
- AC4: `TestCatchUpIdempotentAfterPartialRun` injects a failure after thread k, reruns, and checks that the dump equals a clean run (`dbtest.DumpProjections`).

### Interactions
Consumes C2WW5's `ProjectThread` and BYYJ8's `projection_state`. Provides the `Sweep` hook to C2WW5. CCBYX orders it at startup, and CCBZ8 surfaces `Report` and `Writer.Lag`. `cmd/ketju/fsck.go` has a `DriftBytes` placeholder that could reuse the classification later. That is not in scope here.

### Open items
Whether corruption found at startup should block serve is not stated. The plan logs it and serves, because the log, not the DB, is the source of truth. With `fsync = never`, a crash can make this case ordinary rather than corrupt. The message should say so.

### Settled in grooming (2026-09-24)

- Corrupt threads, where the log is shorter than the projection, are quarantined: log at error level, report on /healthz and in fsck, serve that thread as 503, keep serving the rest (docs/03, decided 2026-09-24).
- The 2 s bound is measured by a benchmark without -race. The -race test suite checks correctness only.
