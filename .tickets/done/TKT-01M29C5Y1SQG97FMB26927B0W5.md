## Description

On start, compare each thread's `projection_state.log_length` against the real log and replay the gap. A crash between a log write and a database write leaves exactly this gap, and closing it on startup is what makes the asynchronous projection safe.

The scan has to stay cheap with ten thousand threads on disk. Reading an index header is 32 bytes and a `stat()` is free, so this is a directory walk rather than a full open of every thread.

## Acceptance criteria

- [x] A thread whose log is shorter than its projection_state is reported as corruption rather than silently accepted
- [x] Catch-up is idempotent if the process dies partway through it
- [ ] A gap between projection_state and the log is closed before the listener accepts requests (the server does not serve while catching up, decided in grooming 2026-09-24), and the catch-up logs how many threads it closed and how long it took
- [x] Catch-up over ten thousand threads with no drift completes in under 2 s on the CI runner without opening every log, enforced by a test or benchmark that fails above that bound

## Implementation plan

Revised at claim (2026-09-24), after reading the code. The decision stands: catch-up finishes before the listener accepts requests (docs/03 "Durability and recovery", already written down there).

### Approach
1. `(*Writer).CatchUp(ctx, reopen Recover) (Report, error)` in `internal/events/projection/catchup.go`. One query, the new sqlc `ListProjectionLengths`, reads every projected length.
2. `walk` reads `threads/xx/yy/` with `os.ReadDir` at each of the two shard levels. The size comes from `DirEntry.Info()`, and the id from `threadid.FromLogPath`, which also refuses a file in the wrong shard. No log is opened on this pass. Anything that is not a log or an index is reported in `Report.Strays` and logged at warn.
3. Classify each thread:
   - size equal to the projected length: skip;
   - size smaller: quarantine;
   - a projection row with no log: quarantine;
   - no row, or size larger: a gap.
4. A gap is opened through `reopen`, which serve supplies from the thread cache, the one writer a log may have. The cache repairs a torn tail, and `Actor.LogLength()` is the true length.
   - Projection runs up to that length, not the stat size. ProjectThread refuses a damaged frame, so projecting to the stat size would fail on the torn bytes.
   - A reopened length equal to the projection means the gap was only a torn tail. A shorter one is corruption.
   - The projection goes through `w.project`, so a thread that fails joins the behind set and `Run` retries it.
5. Quarantine:
   - The writer keeps the set; each catch-up replaces it, so a repaired thread leaves at the next.
   - Each corrupt thread gets an error line naming it, both lengths, and that `storage.fsync = "never"` can make this ordinary.
   - `threads.Service.Quarantined` makes all four thread endpoints answer 503. The check comes after the read check, so a hidden thread stays 404.
6. Each thread's gap is closed in its own transaction, the one ProjectThread uses. Context cancellation stops between threads, and a rerun resumes.
7. The summary goes in one info line (scanned, closed, bytes, corrupt, failed, strays, elapsed). `LastCatchUp()` keeps the last Report for healthz (CCBZ8) and metrics.
8. The Sweep hook stays with serve (CCBYX), which builds it as `w.CatchUp(ctx, reopen)`. Writer's options are unchanged.

### Tests
`catchup_test.go`, plus a quarantine test in `internal/web/api/thread_test.go`.
- AC1:
  - `TestLogShorterThanProjectionIsCorruption` covers a truncated log and a missing one: the rows are untouched, the thread is quarantined, the error line names it, and nothing is opened. A repaired thread leaves quarantine at the next catch-up.
  - `TestCutLogWithATornTailIsCorruption` covers a file longer than its projection whose whole frames are shorter.
  - `TestQuarantinedThreadIs503` checks the endpoints.
- AC2: `TestCatchUpIdempotentAfterPartialRun` stops a run at the third thread; the resumed run's dump equals an uninterrupted one.
- AC3: the "before the listener" half is serve's test. The logging half is `TestCatchUpClosesGap`'s summary-line check.
- AC4:
  - `TestCatchUpTenThousandNoDrift` runs under -race and checks nothing is opened.
  - `TestCatchUpTenThousandUnderBound` (`catchup_bound_test.go`, `//go:build !race`) fails above 2 s. A new CI step runs it with -v.
- Also: `TestTornTailIsNotAGap`, `TestUnopenableGapIsReportedNotFatal`, `TestFailedProjectionStaysBehind`, `TestCatchUpReportsStrays`, and `TestCatchUpEdges`.

Built `CatchUp` in `internal/events/projection/catchup.go`, with the quarantine answering 503 in `internal/service/threads`, the `ListProjectionLengths` query, and a CI step for the bound.

Decisions made while building, with the alternatives that lost:
- **A gap is projected to the length the cache's open reports, not to the stat size.** ProjectThread refuses a damaged frame outright, since damage is never skipped, so a torn tail would have made every crashed thread fail catch-up. Projecting to the stat size lost for that reason. Having catch-up truncate the tail itself also lost: catch-up would become a second writer to the log.
- **The reopen hook is a parameter.** Serve passes a closure over the thread cache. Putting a cache in `Writer`'s Options lost: it would tie the projection package to the cache and change a constructor other tests use.
- **A reopened length below the projection is corruption.** A cut log can end in torn bytes that make it look longer than its projection. `TestCutLogWithATornTailIsCorruption` covers this. That test removes the .idx, because an index still claiming the old length is recovery's to judge, not catch-up's.
- **An unopenable thread is Failed, not quarantined.** Quarantine is the settled answer only for a log shorter than its projection. An unopenable thread is logged with its cause and does not stop startup.
- **The 503 check sits after the read check.** Before it, a 503 would tell a viewer who may not see the thread that it exists.

Measured: 10,000 threads with no drift in 50 ms locally, without -race. Under -race the same test takes about 4 s, which is why the bound is only enforced in the non-race step.

Answered review 453. The fix for review 448 held an unopenable gap at the walk's size, which caused both findings.

- a thread already at that length leaves the behind set through project;

**agent:claude-code/phase1-run-415af6aa** at 2026-09-24T17:17:31Z

Answered review 456 (medium): a header-only log with no projection_state row skipped the gap path.

The finding was right that such a log was skipped silently. Its suggested fix, projecting it, would be wrong. A header-only log is a crash between creating the thread's files and appending ThreadCreated. ProjectThread has no frame to apply and returns without recording state, so each catch-up would count the thread as a closed gap and find it open again at the next.

What was done instead: catch-up reports such threads in a new `Report.Unfinished`, logs one info line each, and counts them in the summary line. It neither projects them nor holds them for retry. A log with no row and more than a header is still a gap, as before.

Test: TestHeaderOnlyLogIsUnfinished checks the report, that nothing is held, that no row is written, and the log line.

## Summary

Projection catch-up (Writer.CatchUp) closes every gap between a log and its projection. One query and a stat-only walk mean a thread with no drift is never opened: 10k threads take 50 ms, and a non-race CI step holds a 2 s bound. A gap is opened through the thread cache, which repairs a torn tail, and projected to the true length. A log shorter than its projection, or a projection with no log, is quarantined: logged at error, served 503 by every thread endpoint after the read check, with the rest still serving. Each thread's gap is its own transaction, so an interrupted run resumes. AC1, AC2 and AC4 are met. AC3's before-the-listener half is serve's (TKT-01M29CCBYX), and fsck reporting is drafted as TKT-01M3A054TR.
